The infrastructure has its own deletion candidates. Pull-request contract gates default to skipping execution; the CLI exits zero while correctly recording `passed:false`. The green job is therefore validation-only, not release qualification. Three explicit release test selections include `--passWithNoTests`. The Bun SuperApp smoke executes only a metadata validator. Upstream drift certification only checks whether Git merges. The detailed [infrastructure review](infrastructure.md) gives each recommendation an `I01`–`I12` ID.

The static evidence validator also accepted a scratch document with a year-2000 timestamp, a non-commit value, a syntactic GitHub run URL and duplicate reviewers. That does not invalidate the separate exact-artifact publishing/acceptance system. It proves that counting metadata/reviewer lines is not release evidence. Preserve actual tarball-byte checks, authenticated run binding, tamper rejection and downstream execution.

The useful survivor set should be built around supported failures, not around keeping one file from every old category:

- Generate and migrate a real workspace; compile/build it and execute the public consumer path. Preserve user-file ownership, rollback, preflight and concurrent-edit protection.
- Exercise actual Node/workerd SSR, raw no-JavaScript remote content, hydration identity and native localized navigation. Assert the behavior the user sees.
- Keep compact BFF transport/security cases for identity, authorization, cancellation, redaction, replay and failed dependency recovery.
- Keep native package/declaration acceptance that genuinely uses published exports and dependency closure. Source-mode unit tests serve a different purpose.
- Keep one compact validator matrix per implementation, plus a small public boundary check. Avoid replaying every scalar permutation through every adapter and build format.
- Keep canonical fork ownership/import/budget enforcement, including meaningful invalid git fixtures. Remove assertions of today's live totals.
- Keep the exact-cohort Tractor acceptance required by repository policy, preserving its visible UI.

A count is not automatically bullshit. Bounded retries, unique route identities, exactly one wire header, no duplicate stylesheet, or byte-identical user files after a failed migration can express the actual requirement. Likewise, source text is legitimate input to a linter/parser, and emitted code is a generator's output. The bad pattern is a proxy that stays green when the supported behavior breaks, or a second copy of an already-protected contract that adds maintenance without useful failure isolation.
