## Duplicate families to collapse

**Cloudflare fixture explosion.** `cloudflare.test.ts` is 4,197 lines, with approximately 900 lines of fixture setup before the first test. It writes fake Effect source at 60–196, a fake dispatcher at 198–277, fake Drizzle classes at 332–379 and a fake Drizzle package at 516–568. Each scenario repeats this setup. The actual preset preparation/staging/entry generation happens at 862–900; there is no actual Effect/Drizzle build. Retain the generated entry as the system under test, then use much smaller fixtures for dispatch, security, assets, fragments, and dispatcher lifecycle.

The request cases at 2176/2280 can share one method table. Missing image/HTML handling at 2239/2262 can share another. Dispatch at 2410 repeats the dashboard request at 2371. Backend asset staging at 1782 overlaps 1695. Missing binding at 3703 is a weaker version of the response/event case at 3736. Security defaults recur throughout otherwise unrelated CSS/asset cases. These are opportunities to remove entire redundant fixtures, not merely shorten titles.

**Verifier grammar multiplied into deployment fixtures.** Much of the 54-case output-verifier suite constructs a complete output tree to test one parser distinction: static versus dynamic imports, ambient versus locally bound loaders, alias/destructuring/computed/optional-call spellings. These distinctions can be valuable parser coverage. Put them in a compact direct-parser table and retain one verifier integration for module-closure acceptance/rejection. Do not retain a full deployment fixture for each grammar spelling.

**Build formats multiplied across semantics.** `empty-producer-release.test.ts` runs seven case families against source, CJS, ESM, and esm-node: 28 registered cases. Its invalid-asset loop checks 11 invalid URLs both alone and mixed with a valid declaration in every format. Run semantic behavior once; separately prove a minimal public consumer works for each actually supported package format. The backend build matrix likewise emits four near-identical topology/identity combinations while the main build suite repeats their manifest assertions.

**Builder and preset introspection.** Default mode/cache/native loader/React compiler/precompression settings recur across `builder/default`, `environment`, `reactCompiler`, app `config/default`, `adapterPrecompress`, and `presetUltramodern`. Own each meaningful input/output boundary once. A callback count or constructor-name inventory is not a substitute for a transformed CSS result, a rejected type error, compressed bytes, or a usable module alias.

**Package acceptance spread across weak probes.** Consolidate export-existence checks, export-map/source-key checks, live repository imports, template directory inventories, and the expensive rslib package build. Build once, pack once, install into an isolated consumer, execute imports/resolver behavior, and run a real compiler against the declarations. Exact ten-template or two-file inventories do not establish deployability.

**Envelope and identity repeated at every layer.** Keep low-level hashing/size/canonical ordering/parser boundaries in the core envelope suite. Keep one producer→staging→verifier chain for Node and Cloudflare, and the integration-only symlink/private-output boundaries. Cases 783/819/978 in the integration suite repeatedly mutate bytes; 819 claims dependency tampering but mutates only `index.js` and Wrangler config. The fake staging modules are adequate for envelope logic, but they are not actual application-build acceptance.

## Coverage worth protecting

Do not purge tests merely because they inspect generated output, count something, or use a controlled dependency. The relevant distinction is whether the assertion protects observable behavior and whether the test actually reaches the owning implementation.

- **Native type checking:** `native-type-checker.test.ts:13,62` invokes the real compiler, gets TS2322 from project references, repairs it, and checks emit/startup contracts. `native-type-checker-watch.test.ts:10` drives real watch error→clean→error transitions after changing a referenced type-only input.
- **Browser CSS and route assets:** `css-extract-runtime-plugin.test.ts:84` builds the real Rspack loader and tests SSR stylesheet reuse without crossing URL origins/queries. `builder/routerPlugin.test.ts:83` reads a real emitted route manifest. A duplicate-link count here measures observable behavior; a filename count elsewhere does not.
- **Real Cloudflare worker bundling:** verifier `:1007` compiles minimized/unminimized worker entries, executes imports, checks shared module identity, and excludes a poisonous unused export. Keep the behavior; remove its exact four-filename inventory. Keep real collision prevention at 1065, explicit unsupported lazy output rejection at 1121, and filesystem escape rejection at 1429.
- **Generated Cloudflare dispatch and streaming:** `cloudflare.test.ts:2371` proves SSR wins over a poison-like SPA asset fallback; `:2436` validates SSR HEAD behavior; `:3079` proves service dispatch precedence; `:3226` verifies prop-bearing fragment provenance; `:3488` blocks body consumption to prove late CSS does not force HTML stream draining; `:3970` proves dispatcher disposal, retry and successful cache recovery. These hit the actual generated runtime despite controlled dependencies.
- **Package/deployment boundaries:** `cloudflare-output-contract.test.ts:127` stages, verifies, imports, and requests actual generated worker output. `server-plugin-interop.test.ts:12` executes generated launchers in fresh Node processes for CJS/ESM interop. Both are stronger than plugin/export inventories.
- **Real module relocation and artifact identity:** npm aliases `:245,331,392` exercise owner-specific versions, scoped store layout, and output escape rejection. Backend federation `:276` builds a container, serves it over HTTP, and loads it through the actual consumer. Preset `:298` proves changed delivery identity changes executable minimized bytes and their contenthash.
- **Integrity boundaries:** envelope integration `:562` rejects symlink rebinding even when target bytes are identical; `:875` rejects private envelope leakage into public assets. Release identity `:124,179` uses real Git to reject dirty-source identity and mismatched revisions. The compact core envelope suite independently calculates expected hash/size rather than merely calling the production helper twice.

## Infrastructure limits and follow-up acceptance

The audited checkout has no installed package dependencies. This was a complete static review of the assigned tests and relevant implementations, with one cheap Node falsification probe for ancestor-module fallback. No suite was executed and no timing or CI pass claim is made.

Node imports plus fake `ASSETS` do not establish workerd compatibility. In particular, `cloudflare.test.ts:3056` imports a handwritten CommonJS worker under Node, where `__dirname` and `__filename` already exist; it cannot prove those globals survive a real module-worker deployment. Verifier tests that set `importWorker: false` and accept builtin names or declared nonexistent dependencies prove static metadata policy only.

Some fetch mocks fall through to the original global fetch for unexpected URLs. Make unexpected requests fail deterministically. The Rsdoctor and tsgo builder tests create compilers without closing them. The native watch test does close resources; preserve that cleanup. Rslib acceptance performs a full package build with a 120-second timeout for mostly `typeof` checks; share that build if the packed-consumer replacement is accepted.

Both app-tools package tsconfigs include `src` rather than these tests. Type annotations and `satisfies` inside runtime-transpiled tests therefore do not independently provide type-test coverage. The explicit native compiler tests do.

The proposed deletion list is the **34 T3 scenario/assertion rows** in JSON, followed by replacement or consolidation of **104 T2 rows**. These are review units, not a promise to remove 138 registered tests. No deletion should discard the preserved inherited scenarios or the strong predicates embedded in mixed suites.
