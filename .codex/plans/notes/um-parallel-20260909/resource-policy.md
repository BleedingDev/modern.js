# Dispatch and resource policy

The configuration resolves to 50 threads and depth 3. Dispatch at most 40 active leaf workers, leaving ten slots for primary/integration/checking/recovery. The root creates all workers; no nested spawning is authorized by this graph. A ready queue may exceed 40. Never launch the entire queue at once.

Run a continuous ready queue. Prefer actual critical-path blockers, then tasks that release useful successors. A conceptual wave is explanatory only. Integrate a completed packet and dispatch its next node while unrelated audits or repairs continue. Do not wait for all 45 audits to finish. The initial launch is root baseline freeze plus five independent consumer evidence workers; baseline completion opens 45 identity audits, checker work and the root integration service. Fill available worker slots immediately.

The baseline node only fixes source/base/hash/resource inputs. It must not absorb every per-file legal audit or become a full-program architecture phase. Each route gate completes only with an accepted legal route, exact file reservation and delivered/frozen consumed interface facts. An unresolved report leaves that route pending. Register a real missing upstream seam as a separately tracked, bounded template instance; add its exact dependency edges and revalidate before launching its consumers. Upstream submission still requires explicit authorization under AGENTS.md. Review waits park that seam’s worker; unrelated nodes keep running.

The root owns `gate-shared-service` and `gate-source-assembly`. The first establishes the available shared-write queue; it does not claim source integration complete. The same root handles reviewed manifest export-map, generated lockfile/cohort/changelog/mirror and ledger batches continuously. One batch mutates shared files at a time. Each batch has exact source/target identities, legal capacity, narrow verification and a receipt. Source-barrel files remain with their exact inventory owner unless ownership is explicitly transferred. Final assembly closes this service only after all required handoffs and genuine upstream source have landed.

Exact original source ownership is in ownership.json. Broad `target_scope` values are proposals, never write permissions. Grant exact new destination paths once, update the ownership registry and dependency selection, and check against every active reservation before writes. Prefer existing fork packages; a new package requires its own justified responsibility. Shared public contracts have one writer. A missing provider implementation becomes a concrete predecessor; a proposed signature does not make an absent API callable.

Use private mutable workspaces and artifact/build roots for concurrent compilation and verification. A shared read-only source ref may be reused; generated output, package installs, indexes and build directories may not be shared between writers. Record each host/resource lease and its owner in operator-log.md. Resolve physical CPU/memory/storage capacity at launch; queue heavy jobs when those actual resources are unavailable while read-only/source work continues. Do not invent a fixed two-worker limit or cancel another agent’s work to free a slot.

ERP, Tractor and conflicting update runtime phases require `host-default-runtime-ports` on the same host. Use genuine supported isolated environments to run them concurrently; otherwise queue those phases behind the mutex. Never remap application ports or add local configuration to manufacture concurrency. Source and published jobs are distinct. A present canonical Tractor repository requires its exclusive ownership lease, update/validation and preserved UI; another agent’s active checkout is not disposable.

Metrics need a dedicated benchmark host or scheduler-wide quiescence of competing build/test/install jobs on that host for each sample. A mutex used only by the metrics worker is insufficient. Unavailable comparable measurements remain explicit; structural graph width is not a promised speedup.

The final-ref check matrix has 13 independent verification nodes: eight component areas, generator, publication tooling, types/exports, style/ledger and the required native-platform matrix. Give check IDs one owner to avoid duplicate suites. The platform owner expands only justified real OS jobs after exact commands and runner leases are known. Every job uses the same immutable final ref and private mutable outputs. None may edit source to make verification pass.

On one avoidable overlap, narrow the reservations; on a second in the same area, serialize that area. Infrastructure failures shrink only the affected resource pool. Missing approvals, unlanded upstream source and required runtime evidence remain real blockers. Never advance a node merely because an agent returned, a timeout elapsed or a plan exists.
